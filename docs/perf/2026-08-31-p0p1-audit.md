### P0-3: JWT 黑名单 (commit 225b101)
**P0-3a — gateway 路径** (生产链路):

- **gateway 路径已 work, 无需修改**

**P0-3 — JwtAuthenticationFilter 修复** (commit 225b101):
- 直连模式备用 filter, 之前完全没查 blacklist
- 修复: 增加 StringRedisTemplate, validateToken 前查 Redis blacklist

**P0-3b — 端到端验证发现 + 修复** (commit 370dcd1):
- 端到端实测 (2026-08-31 04:00): blacklist 命中后, **HTTP 200 + controller 仍被调用**
  (system log: `SysUserController.getUserDetail(..) | Status: 200 | Duration: 41ms`)
- **根因 1**: 业务模块实际注册的是 `HeaderAuthenticationFilter` (从 X-User-Id 取身份),
  不是 `JwtAuthenticationFilter`. P0-3 修复在错误的 filter 上.
- **根因 2**: P0-3 原实现只 short-circuit filterChain, 未写 401 status.
  controller 仍执行 → @PreAuthorize 拒绝 → 业务抛 401 body, 但 HTTP 200.
- **修复 (双层)**:
  1) `JwtAuthenticationFilter.writeUnauthorizedResponse`: 直接 401 status + body, 不进 controller
  2) `HeaderAuthenticationFilter.extractJtiFromBearer + writeBlacklistUnauthorized`: 业务模块实际 filter,
     入口处先查 blacklist, 命中直接 401
- **部署验证待定**: 本会话内 system module 启动时在 Nacos 3.x gRPC client + JDK 25 netty 阻塞
  (与本修复无关), 需 Nacos 稳定后重跑端到端
