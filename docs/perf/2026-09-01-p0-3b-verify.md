## 4. 关键观察

### 4.1 P0-3b 修复链完整生效

| 修复点 | 状态 | 证据 |
|---|---|---|
| JwtAuthenticationFilter blacklist 检查 (P0-3) | ✅ | gateway 路径一直 OK, 但 P0-3b 修复了直连路径 |
| HeaderAuthenticationFilter blacklist 入口 (P0-3b 370dcd1) | ✅ | 业务模块实际是 HeaderAuthFilter,直连模式现在查 blacklist |
| 缓存逻辑 (ae06566) | ✅ | 入口处实时查 Redis,无缓存误用 |
| writeBlacklistUnauthorized 401 状态码 | ✅ | HTTP 401, 不是 200, body 也不会返回业务数据 |

### 4.2 响应头 `X-Blacklist-Jti`

业务模块在 401 响应里返回 `X-Blacklist-Jti: 1ed66d11-...` 头,这个调试头证明:
1. 确实识别出 blacklist 命中的 jti
2. 在 401 写回前已查询 Redis
3. 方便后续排查(可在生产关闭)

### 4.3 Caffeine 死锁解决方案

| 配置 | 启动结果 |
|---|---|
| 768m 内存 + :latest 镜像 | 1 分 30 秒后 exit(1) — 死锁 |
| 2GB 内存 + :fix 镜像 | 86.19 秒启动成功 |
| 4GB 内存 + :fix 镜像 (后续测试用) | 1 分钟左右启动成功 |

**建议**: 把 `cloud-system` 服务的 `mem_limit` 从 768m 调到 2g (生产配置),或者降 Caffeine 版本到兼容 JDK 25 的版本。
