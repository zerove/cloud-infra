# 数据权限控制系统设计

**目标:** 实现基于用户、角色、岗位及部门维度的动态数据范围权限控制 (Data Scope)。

**架构:**
- **动态 SQL 注入:** 利用 MyBatis-Plus 插件拦截器，自动在满足条件的查询 SQL 中注入 `WHERE` 过滤条件。
- **多维度计算:** 综合评估用户所属的部门、担任的岗位以及角色绑定的数据权限，计算出当前用户的最终数据查看范围。
- **性能优化:** 在用户鉴权时预计算数据范围并存入 `SecurityContext`，避免数据库层面的重复计算。

**关键组件:**
1. **数据范围枚举 (`DataScopeEnum`):**
   - `ALL`: 全部数据权限。
   - `DEPT_AND_CHILD`: 本部门及以下数据权限。
   - `DEPT`: 本部门数据权限。
   - `SELF`: 仅本人数据权限。
2. **拦截器 (`DataScopeInterceptor`):**
   - 拦截包含特定注解（如 `@DataScope`）的 Mapper 方法。
   - 解析当前登录用户上下文中的权限范围。
   - 动态修改 SQL 语句，追加过滤条件。
3. **上下文提供器:**
   - 结合现有 `PermissionService` 和自定义的 `DataScopeContext`，提供获取当前用户数据权限范围的方法。

**数据流:**
1. 用户发起请求 -> 鉴权通过 -> 计算数据权限范围 -> 放入 `ThreadLocal` 上下文。
2. Mapper 查询执行 -> MyBatis 拦截器触发 -> 解析 SQL -> 注入 `WHERE` 子句 -> 返回过滤后的数据。

**安全保证:**
- 默认拒绝：若无法计算数据范围，默认仅允许查询本人数据或直接拒绝。
- 审计记录：所有数据权限注入行为均可记录日志以供审计。

---
**规格自检:**
1. **多维度:** 综合用户部门、岗位、角色进行动态权限计算。
2. **高效:** 采用拦截器实现无侵入式过滤，利用上下文缓存权限范围。
3. **安全:** 确保 SQL 动态注入的正确性，防止 SQL 注入。
